cra-tmf-archive

TMF 智能归档

CRA · TMF 归档助手

把一个“待归档”文件夹整理成可以上传 TMF 的文件包，并留下每个文件从哪来、为什么这样命名的记录。

需要用户提供

  • 待归档文件夹（PDF 为主）。
  • 归档规则表（Excel）：文件类型、TMF 分区编号、归档目录、命名规则。没有规则表时先问用户要，不自己发明规则。
  • 项目号、中心号（文件里读不到时问用户）。

步骤

  • 清点：列出每个文件的文件名、页数、大小、是否有文字层。算文件哈希，找出内容完全相同的文件。
  • 逐页识别：读每一页的文字，判断文件类型，并取出命名要用的关键信息（日期、批件号、姓名、版本号、设备编号等）。没有文字层的页不要猜类型，列为“待人工确认”；用户同意时才做 OCR，并注明 OCR 文字需对照原件。
  • 判断是否要拆分：一份 PDF 里有两种以上文件类型时，给出拆分方案（第几页到第几页是什么），拆分后页数相加必须等于原文件页数。
  • 去重：内容相同（哈希相同，或文件类型和关键标识全相同）的只保留一份，其余列入“重复文件”，不删除原件。
  • 命名和归位：严格按规则表生成新文件名和归档目录。命名要用的信息缺失时不生成文件名，列入“待人工确认”。
  • 生成文件包：在输出文件夹里按归档目录放好复制并重命名后的文件；拆分的文件用拆分后的版本。
  • 质量检查：每个输出文件重新打开核对页数；文件名里的日期、编号回到正文再核对一遍；记录空白行未划斜杠、签名或日期缺失、复核人为空等需要人工处理的情况。

产出

  • 归档清单.xlsx：原文件名、页码范围、文件类型、关键信息、新文件名、归档目录、依据（页码）、状态（已归位/待人工确认/重复）。
  • 待人工确认清单.xlsx：文件、页码、原因、建议做什么。
  • 重复文件清单.xlsx：重复的文件、与谁重复、判断依据。
  • 按归档目录整理好的文件夹。

通用规则（每次都要遵守）

  • 只处理用户指定文件夹里的文件。原始文件不改名、不移动、不删除、不覆盖；所有产出写到用户指定的输出文件夹（没指定就在输入文件夹旁新建“TMF归档_输出_YYYYMMDD”）。
  • 只写文件里实际看到的内容。看不清、读不出、找不到的写“未能确认”，不推测、不补全、不编造日期、编号、姓名。
  • 每条结论都要带依据：文件名 + 工作表或页码 + 行号。
  • 不做医学判断和合规结论，只列事实并标“待人工复核”。
  • 不把任何账号、密码、受试者身份信息写进产出文件或回复；不登录任何业务系统，除非用户明确要求并自己完成登录。
  • 不安装软件、不联网上传文件，除非用户明确同意。
  • 结束时用中文报告（格式见“最后的报告”），并提醒：以上是本地规则给出的建议，必须人工复核后才能使用。

最后的报告

按下面的格式用中文汇报，数字要和产出文件对得上：

输入：<文件数和类型>
产出：<文件名列表，放在哪个文件夹>
清点：<N 个文件，共 M 页>
识别：<各文件类型数量>
拆分：<哪些文件拆成了什么>
重复：<哪些文件重复>
已归位：<N 个>
未能确认 / 待人工复核：<逐条列出，没有就写“无”>
未处理的文件及原因：<没有就写“无”>
用时：<开始时间 – 结束时间，约 N 分钟>
提醒：以上是按规则给出的建议，需人工复核。

临床试验文件核查

CRA · 研究者文件夹核查

在监查访视前后，把“应该有什么”和“实际有什么”对一遍，再查几条日期先后逻辑。

需要用户提供

  • 应有文件清单（Excel）。
  • 文件夹（按文件名核对；需要看正文时要说明哪些文件打开看了）。
  • 可选：伦理批准版本登记、ICF 签署登记表、人员资质登记表。

步骤

  • 文件齐全性：按应有清单逐项在文件夹里找。找到的写出文件名；没找到的列入缺失清单。“每人一份”的项目（简历、GCP 证书）要按人员名单逐人核对。要求历史版和现行版都有的，逐个版本核对。
  • 说明核对深度：默认只按文件名核对，在结果里写明“仅按文件名”。用户要求时再打开正文核对版本号和日期，并注明页码。
  • ICF 签署逻辑（有登记表时）：
  • 签署日期当天，是否已有更新版本获批却仍签旧版 → “疑似使用旧版，待人工确认是否需要重新签署”；
  • 首次研究操作日期早于受试者签署日期；
  • 受试者或研究者签署日期为空；
  • 两个签署日期不是同一天 → 只提示。
  • 人员资质逻辑（有登记表时）：授权开始日期早于培训日期；GCP 证书日期或简历签署日期为空；登记表有日期但文件夹里没有对应文件。
  • 不下“方案违背”“严重违背”之类的结论，只写事实和“待人工复核”。

产出

  • 文件缺失清单.xlsx：应有项目、要求、实际找到的文件、缺什么。
  • 核查问题清单.xlsx：序号、类别（文件/ICF/人员）、涉及对象、事实描述、依据（文件、工作表、行号）、是否待人工复核。

通用规则（每次都要遵守）

  • 只处理用户指定文件夹里的文件。原始文件不改名、不移动、不删除、不覆盖；所有产出写到用户指定的输出文件夹（没指定就在输入文件夹旁新建“文件核查_输出_YYYYMMDD”）。
  • 只写文件里实际看到的内容。看不清、读不出、找不到的写“未能确认”，不推测、不补全、不编造日期、编号、姓名。
  • 每条结论都要带依据：文件名 + 工作表或页码 + 行号。
  • 不做医学判断和合规结论，只列事实并标“待人工复核”。
  • 不把任何账号、密码、受试者身份信息写进产出文件或回复；不登录任何业务系统，除非用户明确要求并自己完成登录。
  • 不安装软件、不联网上传文件，除非用户明确同意。
  • 结束时用中文报告（格式见“最后的报告”），并提醒：以上是本地规则给出的建议，必须人工复核后才能使用。

最后的报告

按下面的格式用中文汇报，数字要和产出文件对得上：

输入：<文件数和类型>
产出：<文件名列表，放在哪个文件夹>
文件齐全性：<应有 N 项，齐全 N 项，缺失逐条列出>
核对深度：<仅按文件名 / 已打开正文的文件>
ICF 签署：<逐条>
人员资质：<逐条>
未能确认 / 待人工复核：<逐条列出，没有就写“无”>
未处理的文件及原因：<没有就写“无”>

试验药品智能核对

CRA · 试验用药品管理核对

把药品相关的几张表放在一起对账，每个问题都指到哪张表第几行。

需要用户提供

  • 接收记录、发放回收记录、库存盘点表（Excel/CSV）。
  • 温度记录（Excel/CSV；PDF 或照片只在能读出文字时处理）。
  • 储存温度范围（例如 2–8℃）和盘点日期。没给就先问，不默认。

步骤

  • 读表并确认列：列出每张表的列名和行数，说明把哪一列当作批号、数量、日期。
  • 按批号对账：账面库存 = 接收数量 − 发放数量（回收的药不计回可用库存，除非用户另有说明）。与盘点表的账面数、实盘数分别比较。
  • 逐行检查发放回收记录：
  • 回收数量大于发放数量；
  • 发放日期晚于该批号有效期；
  • 批号为空，或批号不在接收记录里；
  • 回收数量或回收日期为空 → 记为“尚未回收/待确认”，不当成 0。
  • 检查温度记录：超出范围的读数（写出日期、时间、读数）；缺失的日期或时段。连续超温时长只有在数据足够时才计算。
  • 不判断超温是否影响药品、过期后发放如何处理，这些写“待人工按方案和药品管理手册判断”。

产出

  • 药品核对问题清单.xlsx：序号、问题类型、涉及批号/受试者、事实描述、依据（文件、工作表、行号）、是否待人工复核。
  • 批号对账表.xlsx：批号、接收、发放、推算账面、盘点账面、实盘、差异。

通用规则（每次都要遵守）

  • 只处理用户指定文件夹里的文件。原始文件不改名、不移动、不删除、不覆盖；所有产出写到用户指定的输出文件夹（没指定就在输入文件夹旁新建“药品核对_输出_YYYYMMDD”）。
  • 只写文件里实际看到的内容。看不清、读不出、找不到的写“未能确认”，不推测、不补全、不编造日期、编号、姓名。
  • 每条结论都要带依据：文件名 + 工作表或页码 + 行号。
  • 不做医学判断和合规结论，只列事实并标“待人工复核”。
  • 不把任何账号、密码、受试者身份信息写进产出文件或回复；不登录任何业务系统，除非用户明确要求并自己完成登录。
  • 不安装软件、不联网上传文件，除非用户明确同意。
  • 结束时用中文报告（格式见“最后的报告”），并提醒：以上是本地规则给出的建议，必须人工复核后才能使用。

最后的报告

按下面的格式用中文汇报，数字要和产出文件对得上：

输入：<文件数和类型>
产出：<文件名列表，放在哪个文件夹>
对账：<每个批号 接收/发放/推算账面/实盘/差异>
发放回收问题：<逐条>
温度：<超温 N 次，缺失 N 处，逐条>
未能确认 / 待人工复核：<逐条列出，没有就写“无”>
未处理的文件及原因：<没有就写“无”>
用时：<开始时间 – 结束时间，约 N 分钟>

Excel 自动处理

CRA · Excel 自动处理

把原始导出表按模板整理成汇总表，每个数都能追回到原表的哪一行。

需要用户提供

  • 原始表（.xlsx 或 .csv，可以多个）。
  • 模板（.xlsx）或明确的输出列要求。
  • 计算规则（例如：偏差天数 = 实际日期 − 计划日期，绝对值大于窗口算超窗）。规则不清楚时先问，不自己假设。

步骤

  • 读表并报告结构：每个文件的工作表、表头所在行、列名、数据行数。列名和模板对不上的先列出来让用户确认对应关系。
  • 不动原始值地检查数据，把下面的情况写进“数据问题”，不要悄悄改：
  • 完全重复的行（去重，保留第一行，记录被去掉的行号）；
  • 关键字段为空；
  • 日期无法识别或不存在（如 2025/4/31）、日期是文本；
  • 编号前后有空格、全角半角不一致（比对时按清理后的值，同时记录原始值）。
  • 计算：只对数据完整的行计算。缺日期的行单独统计为“缺失”，不计入超窗，也不补日期。
  • 填模板：保留模板的表头、列宽、合并单元格；每条明细带“来源行号”。
  • 核对：汇总数 = 明细行数；去重前行数 − 重复行数 = 去重后行数；随机回原表抽查 3 行并写出抽查结果。

产出

  • <模板名>_结果_YYYYMMDD.xlsx：按模板填好的结果。
  • 其中或另附“数据问题”表：来源行号、问题类型、原始内容、处理方式。
  • 不覆盖原始表。

通用规则（每次都要遵守）

  • 只处理用户指定文件夹里的文件。原始文件不改名、不移动、不删除、不覆盖；所有产出写到用户指定的输出文件夹（没指定就在输入文件夹旁新建“Excel处理_输出_YYYYMMDD”）。
  • 只写文件里实际看到的内容。看不清、读不出、找不到的写“未能确认”，不推测、不补全、不编造日期、编号、姓名。
  • 每条结论都要带依据：文件名 + 工作表或页码 + 行号。
  • 不做医学判断和合规结论，只列事实并标“待人工复核”。
  • 不把任何账号、密码、受试者身份信息写进产出文件或回复；不登录任何业务系统，除非用户明确要求并自己完成登录。
  • 不安装软件、不联网上传文件，除非用户明确同意。
  • 结束时用中文报告（格式见“最后的报告”），并提醒：以上是本地规则给出的建议，必须人工复核后才能使用。

最后的报告

按下面的格式用中文汇报，数字要和产出文件对得上：

输入：<文件数和类型>
产出：<文件名列表，放在哪个文件夹>
行数：<原始 N 行，重复 X 行，去重后 M 行>
计算结果：<例如 超窗 N 条，逐条列出>
数据问题：<各类型数量>
核对：<汇总数与明细是否一致，抽查了哪 3 行>
未能确认 / 待人工复核：<逐条列出，没有就写“无”>
未处理的文件及原因：<没有就写“无”>
用时：<开始时间 – 结束时间，约 N 分钟>
提醒：以上是按规则给出的建议，需人工复核。

办公文档批处理

CRA · 办公文档批处理

用“信息表 + 模板”批量出文件，缺信息的如实列出来，不替用户编内容。

需要用户提供

  • 信息表（Excel/CSV），一行对应一份文件。
  • Word 模板（.docx），占位符写成 {{列名}}。
  • 文件命名规则（例如 {项目号}_{中心号}_监查访视确认函_{访视日期YYYYMMDD}.docx）。没给就先问。

步骤

  • 读模板：列出模板里所有占位符；读信息表：列出列名和行数。占位符在信息表里找不到对应列的，先报告，等用户确认。
  • 逐行检查：占位符对应的值为空的行，不生成正式文件，列入“缺失清单”（用户明确要求时可以生成并在文件名和正文里标“待补”）。不编造日期、姓名、地址。
  • 生成：按行替换占位符，保留模板的字体、段落、页眉页脚、表格。日期统一成用户指定的格式（默认 YYYY年M月D日，文件名里用 YYYYMMDD）。
  • 检查每一份：打开生成的文件确认没有残留 {{；逐份核对替换进去的值与信息表该行一致（特别是每行不一样的字段，例如访视类型）。
  • 需要 PDF 时再转换，并核对 PDF 页数与 Word 一致；转换工具不可用时如实说明，只交 Word。

产出

  • 生成的文件（放输出文件夹）。
  • 生成清单.xlsx：信息表行号、文件名、是否生成、未生成原因。
  • 缺失清单.xlsx：哪一行缺哪个字段；没有缺失也要生成并写“无缺失”。

通用规则（每次都要遵守）

  • 只处理用户指定文件夹里的文件。原始文件不改名、不移动、不删除、不覆盖；所有产出写到用户指定的输出文件夹（没指定就在输入文件夹旁新建“文档批处理_输出_YYYYMMDD”）。
  • 只写文件里实际看到的内容。看不清、读不出、找不到的写“未能确认”，不推测、不补全、不编造日期、编号、姓名。
  • 每条结论都要带依据：文件名 + 工作表或页码 + 行号。
  • 不做医学判断和合规结论，只列事实并标“待人工复核”。
  • 不把任何账号、密码、受试者身份信息写进产出文件或回复；不登录任何业务系统，除非用户明确要求并自己完成登录。
  • 不安装软件、不联网上传文件，除非用户明确同意。
  • 结束时用中文报告（格式见“最后的报告”），并提醒：以上是本地规则给出的建议，必须人工复核后才能使用。

物流附件打包

CRA · 物流温度记录与校准证书整理

把一批运输附件整理成“每票是否齐全、是否对得上”的清单和两份合并 PDF。

范围

一次只做：一个项目、一个中心、一个日期范围、3–5 票运单。范围更大时分批做。

需要用户提供

  • 批次文件夹（已下载的 PDF）和附件清单（运单号、日期、附件类型、文件名）。没有清单时先按文件夹内容生成一份，请用户确认。
  • 要处理的运单号。
  • 如果要从网页下载：用户自己在浏览器里登录。本 Skill 不接收、不保存、不输入账号密码。

步骤

  • 列清单：每票运单各有哪些温度记录 PDF、校准证书 PDF，页数多少。
  • 逐份打开核对，只记录 PDF 里实际看到的内容：
  • 温度记录里的运单号、温度记录仪（设备）编号、运输起止时间；
  • 校准证书里的设备编号、校准日期、建议下次校准日期。
  • 配对规则：只有设备编号完全一致才算配对。清单里挂在同一票下但设备编号不一致的证书，结论写“不一致”，并把这票的校准证书列入缺失清单。不强行配对，不用别的运单的证书凑数。
  • 有效期：运输日期在校准日期和建议下次校准日期之间写“在有效期内”；否则写“不在有效期内，待人工复核”；证书上没有写的写“未能确认”。
  • 合并：温度记录合并成一份、校准证书合并成一份，按运单日期升序。合并后页数必须等于各份页数之和。未配对的证书是否并入由用户决定，默认并入并在清单里注明“未配对”。
